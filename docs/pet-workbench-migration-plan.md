# 桌宠工作台：原管理页面逐步迁移计划

> 状态：阶段 0 外壳已实现，交互验收待完成（2026-10-25）。页面内容迁移尚未开始。
> **迁移期间保留全部原管理页面；未经用户明确要求，不删除旧页面、旧导航入口或其功能。**

## 1. 目标与范围

桌宠成为日常入口，用户从桌宠打开活动面板、会话、供应商和其他管理能力。现有八个
顶级管理页面按顺序迁移到桌宠工作台；每迁移一项，桌宠侧增加可用入口，原管理页面
继续保留并可正常操作。迁移完成也不自动触发删除，旧界面何时退役由用户另行决定。

“桌宠里的页面”分成三层，避免把完整表单压进 200pt 桌宠或 330pt 信息卡：

1. **桌宠本体**：桌面常驻、活动状态、收起/唤回和少量即时操作。
2. **信息卡**：最近活动、常用跳转、最近会话和轻量设置。
3. **桌宠工作台**：由桌宠或信息卡打开的可调整大小窗口，承载完整页面、列表、表单和
   历史详情。复杂操作在工作台完成，桌宠本体可以继续留在桌面。

当前控制中心就是旧管理页面的主要入口。迁移工作增加桌宠工作台路径，不改变原页面的
持久化格式、配置写入、路由行为、备份规则或数据目录。

## 2. 必须遵守的迁移规则

- **旧页面保留**：旧页面、旧导航及旧操作在每个迁移阶段都继续工作。不得以迁移为由
  删除页面、隐藏入口、删减功能或清理相关代码。之后只有用户明确要求时，才另行评估
  旧页面退役。
- **共用领域实现**：桌宠工作台复用现有 `ProviderStore`、`LocalRouter`、MCP、Skills 和
  sessions 模块。迁移 UI 不复制写入逻辑，不形成两份配置状态。
- **逐页验收**：每个页面单独标记状态。新入口完成对应页面的主要查看和操作、错误与
  加载状态验证，并确认旧页面仍可用后，才把该页标成已迁移。
- **过程可回退**：新入口出问题时仍可通过旧页面完成管理。阶段之间不要求配置迁移，
  不做可能丢失用户数据的自动清理。
- **桌宠仍轻量**：桌宠本体保持小而常驻；大列表和完整表单进入工作台。文件扫描、导入、
  导出、删除等沿用现有 Worker 与确认流程。
- **隐私边界不变**：不增加屏幕、前台窗口、剪贴板或会话正文的桌宠采集；活动状态仍只
  使用明确启用的来源和现有本地数据。

## 4. 实施阶段

### 阶段 0：建立桌宠工作台外壳

- [x] 从桌宠信息卡提供“工作台”入口；主窗口标题栏也可返回工作台首页。
- [x] 把工作台首页接入现有主窗口页面宿主，启动管理窗口时默认显示工作台；八个原
  页面继续由顶部莲花导航直达，首页的八张模块卡也跳转到相应原页面。
- [x] 沿用当前主窗口的可调整大小窗口和按需创建/关闭生命周期；页面共享既有应用级服务。
- [x] 沿用当前主窗口的按需创建与生命周期规则，不改变启动模式和单实例行为。
- [x] 旧控制中心原八个页面和现有导航并行保留，原页面内容与操作尚未迁入。
- [ ] 手动验收：从桌宠信息卡打开工作台、往返切换页面、关闭窗口回到桌宠；确认桌宠位置、
  偏好、托盘与活动状态不变。

### 阶段 1：迁移会话与统计

- [x] 把会话列表、Agent 筛选和详情页嵌入工作台；沿用当前 Worker、请求代次、摘要缓存、
  详情分页、锚点保持、导出和删除确认。
- [x] 把统计页嵌入工作台；沿用本地路由与会话日志用量账本、刷新、同步和清空操作。
- [x] 工作台子页提供返回首页入口；页面可见性分别控制会话扫描、详情加载、统计轮询与账本同步。
- [ ] 手动验收会话筛选、详情滚动、导出/删除，以及统计刷新、同步和两入口间数据一致性。
- 旧控制中心两页继续保留，独立入口和完整内容不变。

### 阶段 2：迁移 Agent 与供应商

- 先迁移 Agent 选择、供应商列表、当前供应商标记和切换。
- 再逐步迁移新增/编辑表单、模型列表、用量配置、连通检测、官方恢复、收编与导入导出。
- 复用现有八工具注册表和工具适配；保留各工具已有 live 文件安全、备份与增量写入规则。
- 验收每种工具的主要增删改/切换路径及失败恢复，不改变 `config.json` 或 live 配置格式。

### 阶段 3：迁移本地路由

- 迁移路由运行状态、端口、故障转移、总开关、逐 Agent 代理开关和最近请求日志。
- 请求日志继续使用本地已有统计；不在桌宠工作台增加请求正文或响应正文保存。
- 验收运行中开关即时生效，禁用 Agent 的路径仍不访问上游或增加统计。

### 阶段 4：迁移 MCP 与 Skills

- 先迁移 MCP 清单、启停与 live 配置同步，再迁移 Skills 中央库和工具侧同步。
- 保留不同 Agent 的能力差异、冲突提示和原有文件安全边界。
- 验收创建、编辑、同步、启停、失败反馈以及旧页面数据一致性。

### 阶段 5：迁移设置与关于

- 把桌宠启动、托盘、外观、活动来源和主题选项放入工作台的设置区域。
- 再迁移路径、导入导出、关于、依赖与许可信息。
- 保留首次启动设置、登录启动项和用户显式启动偏好的现有语义。

### 阶段 6：逐页对照与并行使用

- 对照八个页面逐项核对入口、操作、错误态、权限提示、数据刷新和持久化。
- 更新清单状态，记录未迁移功能和平台差异。
- 工作台达到整体验收后，旧管理页仍保留。是否删除、隐藏或重命名旧页面，等待用户
  后续明确决定，不由本计划自动推进。

## 5. 共通验收条件

每个迁移页面至少满足以下条件，才可标记“已迁移”：

1. 旧页面已有的主要查看与操作都能从桌宠工作台完成，且不会意外省略成熟能力。
2. 读写使用原来的领域模块、Store 和持久化契约；从任一入口修改后另一入口能看到同一状态。
3. 加载、空状态、未知状态、失败反馈、取消和重复触发行为清楚；文件 IO 沿用 Worker。
4. 新页面可从桌宠到达，关闭或返回不丢桌宠位置、外观、启动偏好或托盘状态。
5. 原管理页面仍能到达并完成相同操作；迁移不触发旧页面删除或不可逆数据变更。
6. 对领域行为变化补相应测试；完成项目要求的构建、测试、diff 检查与提交流程。
