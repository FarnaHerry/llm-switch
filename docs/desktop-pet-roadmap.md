# AI 桌宠优先产品与工程路线图

> 状态：产品方向重排（2026-10-24）。本文是桌宠方向的唯一计划来源；已完成的
> 技术批次记录保留在末尾。本文定义目标与顺序，不代表尚未勾选的功能已经实现。

## 1. 产品方向

llm-switch 的第一入口改为**本地 AI 桌面伙伴**：桌宠常驻桌面，帮助用户看见多款
Agent 的活动并快速回到日常工作；主窗口当前承载原有**多 Agent 控制中心**。后续按
[桌宠工作台页面迁移计划](pet-workbench-migration-plan.md)逐步把八个管理页面接入桌宠
工作台。迁移期间原管理页和入口完整保留；只有用户明确要求后才讨论删除。

体验优先级：

1. **桌宠**：启动后的默认入口，提供轻量状态、拖拽、收起和唤回。
2. **信息卡**：桌宠的日常面板，汇总正在工作的 Agent、最近结果和快捷入口。
3. **桌宠工作台（逐步建设）**：由桌宠打开，逐步承载配置、历史、统计和高级选项；
   原控制中心页面在迁移期间并行保留。

桌宠不等于“必须永远置顶”。置顶、轻量隐藏、动画和启动方式都由用户控制。默认
不读屏幕或剪贴板，不主动调用 shell，不把会话正文传出本机。

## 2. 目前的实现与差距

- 启动入口支持桌宠优先 / 控制中心两种模式：新配置和未保存过启动偏好的旧配置
  默认桌宠优先，旧版显式 `petEnabled` 选择继续保留。桌宠优先启动只创建桌宠窗口；
  托盘是否可用不会额外打开控制中心，桌宠创建失败或平台不支持透明窗口时才回退到
  控制中心。新安装的简短设置在用户首次打开控制中心时展示，完成后返回桌宠；可选择
  莲花球/可用时的 Live2D、置顶、登录启动、托盘、本地路由，以及 Claude Code / Codex
  原生来源；登录启动偏好写入当前用户的系统启动项。
- 桌宠已有拖拽、胶囊、信息卡、托盘唤回、成功/失败提示，以及八个 Agent 的分组
  统计入口。信息卡点击 Agent 行可跳至控制中心对应页面。
- 桌宠活动状态可来自 `LocalRouter` 与显式启用的 Claude Code / Codex hooks；今日
  请求与 token 统计仍来自 `LocalRouter`。本机已确认 hooks 会启动 helper，关闭路由的
  spike 有部分结果；逐状态展示、Codex 失败语义和边界行为仍未完成验收。
- **Live2D 当前仅保留技术壳子，整项未完成**：已有独立渲染路径和莲花球失败回退，
  但 `LLMSWITCH_LIVE2D` 默认 OFF，需单独提供 Cubism Native SDK；许可、透明边缘、
  点击命中、其他平台与长期运行都未验收，不能视作已交付皮肤。
- 当前桌宠点击展开信息卡，右键提供快捷菜单；新的日常对话与快捷提问能力尚未实现。

## 3. 目标体验

### 首次启动

- 新安装直接显示桌宠；管理窗口由“打开控制中心”进入。首次进入控制中心时显示
  简短设置，用户完成后回到桌宠。
- 升级安装不覆盖用户明确保存的启动偏好。旧配置缺少新启动偏好时默认桌宠优先；
  用户可在设置中随时改为控制中心启动。
- 透明工具窗口不可用或桌宠初始化失败时，管理窗口保持可见并提供恢复入口，不能让
  应用变成没有可操作窗口的后台进程。

### 日常使用

- idle 时安静呼吸，不弹无关消息；忙碌时显示 Agent 身份和真实活动；完成、失败
  与需要用户处理的状态有清楚且可消解的提示。
- 单击打开信息卡。信息卡优先回答“谁在工作、最近发生了什么、我接下来能做什么”，
  并提供打开 Agent 管理、用量统计和控制中心的入口。
- 右键菜单负责收起/唤回、胶囊切换、设置、退出等桌面动作。用户可关闭动画、置顶
  与活动来源。
- Live2D 是主要角色外观方向；莲花球继续作为低资源、无模型和无 Live2D 构建时的
  内建皮肤。两种皮肤共用同一套状态、信息卡和快捷操作。

## 4. 产品与数据边界

### 活动数据

桌宠状态统一表达为本地活动事件，而不是把单个请求日志当作所有 Agent 的状态：

- `LocalRouter`：保留现有可靠的 streaming、完成、错误和 token 来源。
- 原生 Agent 来源：优先接入各工具官方 hooks / plugin / extension 生命周期事件，
  从 Claude Code 与 Codex 开始；只有官方事件覆盖不足且隐私边界通过验证后，才评估
  本地日志的元数据回退。接入评估、八个工具的公开接口和安装边界见
  [原生 Agent 活动接入调研](agents/activity-integration-research.md)。hook 输入只
  提取状态所需字段，不把 prompt、回复、命令、工具参数/结果或 transcript 路径写入
  桌宠事件流。
- 设置中逐项说明来源、读取路径与可关闭方式。来源未启用或不可用时显示“未接入 /
  未知”，不能伪装成“空闲”。路由和原生来源同时报告同一活动时要去重。
- 所有来源只在本机处理；会话正文仍由现有会话页面按需读取，不为桌宠新增内容
  采集或云端服务。

### 窗口与状态

- 应用级桌宠控制器继续作为窗口、托盘、设置和数据源之间的共享状态所有者。
- 启动选择、退出语义和唤回路径要形成单一规则：托盘主激活优先唤回桌宠；信息卡
  的“打开控制中心”激活管理窗口；用户明确选择“退出”才结束应用。
- Pet 状态区分 idle、streaming、done、error、unknown/未接入、hidden；不同皮肤
  只负责呈现，不各自维护一套业务状态。
- 迁移期间主窗口完整保留现有管理能力；桌宠工作台复用领域模块与持久化契约，不复制
  业务写入逻辑，也不删除旧页面。

## 5. 分阶段实施

### P0 —— 桌宠成为默认入口

1. **固化启动和迁移规则**
   - [x] 增加清楚的启动模式设置与旧配置迁移；新安装和未保存过启动偏好的旧配置
     默认桌宠优先，现有显式选择保持不变。
   - [x] 桌宠先启动；首次打开控制中心时展示简短设置，可配置外观、登录启动偏好、
     托盘和活动来源。
   - [x] 将主窗口改为按需打开；单实例二次启动、托盘激活、关闭/最小化和桌宠退役
     都按同一规则唤回或隐藏。
   - [x] 桌宠创建失败或平台不支持透明窗口时保留可见控制中心；托盘不可用不阻止桌宠启动。

2. **证明桌宠能看到真实工作**
   - [x] 按调研定义的边界建立独立 `src/agents/` 接入层：统一内存事件契约、多
     session 聚合、过期转未知，以及 Claude Code / Codex 的白名单 hook 适配器。
     接入层不提取、不保留或保存 prompt、工具内容和 transcript 路径。
   - [ ] 为 Claude Code 与 Codex 做受控本机 hooks spike；关闭本地路由，各跑一次
     真实任务，验证能观察开始、持续、结束与失败。2026-10-25 部分实测：Codex TUI
     的不调用工具文本任务成功，`/hooks` 显示 Active，跟踪到任务期间与会话退出时
     的 helper；另一个 Codex 只读任务完成了 shell 工具调用。Claude Code 的 stream
     hook 事件标记显示 `SessionStart`、`UserPromptSubmit`、`StopFailure`，请求以失败
     结束。未读取 hook 输入，也未确认各事件到达桌宠可见状态；Codex hooks 没有专用
     失败事件。本机 Codex CLI 为 0.160.1、运行中的 app-server daemon 为 0.164.0，
     代理初始化探测无响应，失败语义来源仍需评估。
   - [x] 将来源事件合并到桌宠轻量状态；区分“没有活动”和“没有数据”，并在
     应用内存中聚合多 session、多个 Agent 与过期事件，不写会话正文。
   - [x] 给 Claude Code / Codex 加独立启用开关与状态说明；只保留状态所需元数据。
   - [ ] 验证真实 Agent 退出、日志轮换以及 hook 触发的边界行为。
   - [x] 给其它六个工具登记接入顺序；路由继续作为通用兜底来源。顺序见
     [原生 Agent 活动接入调研](agents/activity-integration-research.md)。

3. **Live2D（当前只保留壳子，整项未完成）**
   - 当前可用状态：独立渲染路径与失败后莲花球回退；不承诺可交付或跨平台可用。
   - [ ] 明确 Cubism Native SDK 与内置模型的许可和随包策略。
   - [x] Live2D 构建中的模型缺失、加载失败和播放器失败路径显示莲花球与状态说明；
     用户可从信息卡切回莲花球。
   - [ ] 将 Live2D ON/OFF 构建、模型缺失、模型错误、GPU/窗口释放和重新唤回加入
     发布验证；覆盖 Linux、Windows、macOS 中实际支持的平台。
   - [ ] 实测透明边缘、缩放、点击命中、长时间运行、待机资源和模型切换；无可用
     Live2D 时始终能回到莲花球。
   - [ ] 许可未确认或平台尚未验证前，默认发行构建继续使用莲花球，不把私有 SDK
     或不明许可的模型打进包。

**P0 验收**：全新安装直接以桌宠作为日常入口；不启用路由时，至少 Claude Code
与 Codex 的活动能被明确识别；桌宠或托盘失败时仍可打开管理窗口；切换皮肤不改变
状态语义；不读取屏幕、剪贴板或会话正文。

### P1 —— 信息卡成为日常工作面板

- [x] 信息卡展示当前活动、最近完成/失败、Agent、当前供应商与可用的 token/
  用量统计；路由结果给出供应商与实际提取到的 token，原生 hook 结果明确标记
  供应商未知，不填估算值。双来源在同 Agent、同结果且时间相差 3 秒内时合并。
- [x] 最近结果按来源进入路由记录或对应 Agent，Agent 行选中对应工具，使用统计
  进入统计页；打开控制中心时保留桌宠窗口、位置与偏好。
- [x] 信息卡增加会话历史和桌宠设置快捷入口；外观与活动来源设置复用控制中心，
  不把完整配置表单放进小窗。
- [x] 完成提醒支持点击/右键消解、30 秒自动超时、新任务消解与 reduced-motion；
  不使用系统通知打扰用户。

### P2 —— 从桌宠发起 AI 工作

- [ ] 信息卡提供快捷提问，明确目标 Agent/当前供应商，支持流式回答、中断、重试
  与错误提示；首版只做普通对话，不执行终端命令或修改配置。
- [ ] 可配置快捷提示词；发送前显示目标与内容，发送记录保存在本地并可清除。
- [ ] 复用现有供应商/API 能力，不要求所有 Agent 都经过本地路由；鉴权与失败语义
  按工具/协议适配，并验证取消后能停止网络任务。
- [ ] 可选本机事件 API 默认关闭，仅绑定 loopback；调用方可驱动状态提示，不获得
  shell 或屏幕访问权。

### P3 —— 个性与扩展

- [ ] 增加多个合规模型包、切换与导入体验，角色资源与程序分离。
- [ ] 主动搭话默认关闭；如启动，必须支持每日预算、勿扰时段和 streaming 忙碌检测。
- [ ] 视频全屏让位等平台能力有 HuxerUI 公共 API 后再做。
- [ ] 保留莲花球低资源模式；不走数十/数百 MB 的帧序列动画路线。

## 6. 质量门槛

- 空闲桌宠不启动高频轮询或每帧状态重组；活动来源使用有界节流，文件 IO 在
  Worker 执行，过期结果按请求代次丢弃。
- 状态来源与事件保留期限可解释；未知状态不能被呈现成 idle。活动来源异常时不
  影响路由、供应商配置和控制中心。
- 三个平台验证托盘、隐藏/唤回、窗口锚定、拖拽、置顶回退、显示缩放和轻量退役；
  Wayland 等不承诺被动显示/置顶的平台保留明确回退。
- 所有 UI 继续使用项目钉定版本的 HuxerUI 公开 API；一次性 Application 注册只放
  ApplicationHook，UI 页面按应用级服务和窗口生命周期绑定。
- 页面重排不改变现有 Store/Router/MCP/Skills/Sessions 的持久化契约；行为改变仍
  补对应领域测试。

## 7. 保留的非目标

- 不做屏幕、前台窗口或剪贴板感知。
- 不做 TTS/语音交互与无确认的主动命令执行。
- 不做帧序列位图动画。
- 不让桌宠成为唯一管理入口；无托盘、无透明窗口或 Live2D 不可用时控制中心仍可用。
